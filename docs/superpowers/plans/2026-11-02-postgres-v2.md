# v0.2 PostgreSQL·재사용 구조 확장

## 승인 범위

기존 메모리 v1을 유지하고 공통 PostgreSQL 스키마의 v2를 네 언어에 추가한다. 저장소/서비스/HTTP 경계, 영속 사용자·세션·실패 기록, 혼합 언어 검증, 재시작·동시성·장애, 별도 소비 앱 통합이 목표다. 회원가입·비밀번호 재설정·CLI 배포는 다음 범위다.

## 단계와 소유권

1. 주 에이전트가 v2 명세·DDL을 고정하고 전용 로컬 PostgreSQL과 테스트 도구를 준비한다.
2. Python·Go 에이전트가 두 구현의 저장소 경계와 PostgreSQL 어댑터를 구현하고 Python 패키지를 소비 가능하게 만든다.
3. Java 에이전트와 Rust 에이전트가 각각 같은 DB 계약과 PHC 형식의 어댑터를 구현한다. 각 언어의 원자성과 v1 회귀를 자체 테스트한다.
4. 주 에이전트가 v2 공통 API·브라우저·혼합 언어·재시작·공유 제한·DB 장애와 소비 앱을 검증하고 CI PostgreSQL 서비스를 추가한다.
5. 독립 리뷰 후 작업 파일만 커밋·푸시하고 원격 CI와 SHA를 확인한다.

## 검증

- 모든 기존 자체 테스트와 `python3 tests/conformance.py --backend all --browser`
- `uv run --project tools python tests/postgres_conformance.py --browser`: 임시 PostgreSQL, 네 서버, 사용자 2명, 혼합 언어와 장애 시나리오
- 별도 소비 프로젝트의 서버 import·보호 API·React 흐름
- OpenAPI·명세·CI lint, diff 검사, 원격 Actions

## 운영·권한 경계

운영 DB는 변경하지 않는다. 로컬 테스트 PostgreSQL은 작업 전용 임시 데이터 경로와 loopback 포트에서 시작하며 소유 프로세스만 종료한다. 외부 테스트 URL은 DB 이름 prefix를 확인한 뒤에만 reset을 허용한다. 앱 부팅 시 자동 DDL·seed를 하지 않는다. DSN·비밀번호·원문 세션은 로그에 남기지 않는다. 기존 Git 브랜치·사용자 파일·변경은 보존한다.
