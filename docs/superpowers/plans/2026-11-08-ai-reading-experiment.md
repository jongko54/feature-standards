# 신규 패키지의 AI 읽기·재사용·토큰 실험

## 목적과 범위

신규 CLI 0.4.0의 실제 모델 입력·출력 토큰, 문맥 사용, 공개 API 재사용 증거와 통합 성공을 측정한다. 같은 현재 소스의 인증·권한·메모리 목록 앱을 Python·Go·Java·Rust에서 통합한다. Python PostgreSQL 목록 API 자체의 AI 통합, React UI, 외부 사용자의 채택률과 모델 내부 추론은 이번 비교의 측정 대상이 아니다.

초기 상태는 clean main 78686cc60ec18c13e093158a1330e323d8b7c893다. 이 상태에서 만든 CLI 0.4.0 로컬 tarball의 SHA-256은 7ab98af2d4854743bd1641d38f101df9464cad129a409179f402b9f46105b71b이며, sourceDirty/snapshotDirty는 false다. 실제 registry 게시와 구분한다. 이전 0.3.2 실험과 결과는 변경하지 않는다.

## 사전 고정 설계

- manual, catalog_full, catalog_compact 세 조건 × 네 스택 × 두 반복 = 24회 실제 생성.
- 세 조건은 동일한 소스·카탈로그·과제·모델 요청·timeout·도구 환경을 받는다. 차이는 초기 읽기 안내다. full과 compact의 CLI 호출은 compact flag 외에는 동일하다.
- 언어마다 첫 조건 순서를 회전하고 두 번째 반복은 해당 언어의 정확한 역순으로 실행한다. 각 언어의 조건 쌍별 선후 관계는 반전되지만 24회로 모든 위치 효과를 제거하지 못한다.
- 실제 생성은 직렬 실행한다. 의존성은 사전에 정상 빌드로 준비하고 동일 호스트 캐시를 사용한다. 서버 측 prompt cache, 서버 모델 가중치와 외부 시스템 부하는 통제했다고 주장하지 않는다.
- 요청 모델은 앞 실험과 동일한 gpt-6.1-sol, 실행당 timeout 600초다. 관측 모델 ID 부재는 unknown으로 기록하며 모델을 자동 변경하지 않는다.
- 결과를 확인한 뒤 읽기 안내를 개선하면 원래 24회 결과를 유지하고 새 지침·hash·추가 실행을 별도 실험으로 기록한다.

## 측정과 판정

input, cached_input, uncached_input=input-cached, output, total=input+output을 각각 집계한다. cached를 total에 다시 더하지 않고, 불완전하거나 모순된 usage를 0으로 대체하지 않는다. 절감률은 (기준 합계-비교 합계)/기준 합계이며 음수도 보존한다.

전체 토큰 완전 쌍과 두 조건이 모두 성공한 쌍을 나눠 보고한다. 실패율·누락 수·실제 표본 수도 함께 기록한다. 일부 성공만 선택한 수치를 전체 절감률로 발표하지 않는다.

명령 관측은 성공한 실제 argv의 list/context/compact와 상대 문서 참조·hash로 구분한다. 문자열 포함, echo, 실패 명령, 간접 실행을 실제 CLI 사용으로 단정하지 않는다. manual이 CLI를 사용하거나 compact가 full을 다시 읽은 전환도 기록한다.

재사용은 공개 API 정적 호출 증거, 구현 파일의 정확한 복사 탐지, 참조 소스 보존, 독립 143개 HTTP 검사를 분리한다. 정적 호출은 실행 여부나 무중복 구현의 증명이 아니다. 외부 채택률로 해석하지 않는다.

## 구현과 검증

1. tools/core_reading_eval.py와 결정적 테스트를 추가한다. 기존 auth/core 평가기의 기본 의미와 고정된 과거 결과를 보존한다.
2. 별도 에이전트가 tools/reading_trace.py와 그 테스트를 맡고, 다른 에이전트는 방법론·보안 경계를 읽기 전용 검토한다.
3. 기존 auth/core 회귀, 신규 수식·조건·artifact 검증과 실제 packed CLI 검사 후 runner bytes를 Git에 보존한다.
4. 24회 생성·독립 검사·usage·읽기 기록을 private eval-results 아래에 저장하고 매 실행마다 진행 상태를 기록한다. 원문 trace, 생성 코드, 자격증명과 절대 로컬 경로는 공개하지 않는다.
5. 결과에서 읽기 비용·오류가 큰 지점을 고르고 안내를 좁게 개선한다. 추가 실제 실행으로 확인하고 원래 결과와 분리한다.
6. 정제된 결과·한계·개선 내용을 문서에 반영하고 승인된 GitHub 저장소 반영 및 원격 CI를 확인한다. 신규 registry 배포는 포함하지 않는다.

## 별도로 기록할 후속 실험

- 24회는 명시적 라이브러리 사용 지시를 받은 통합 비교다. 별도 discovery suite에서 스택별 1회, 총 4회는 구현 수단을 지정하지 않는다. 동일 저장소·패키지를 제공한 조건의 선택 관찰이며 외부 채택률이나 일반적인 비율 추정으로 확대하지 않는다.
- discovery는 auth·권한·목록의 약한 정적 단서, 정확한 구현 파일 복사, 직접 product route 연결 검토와 HTTP 결과를 나눈다. 미사용과 복사는 선택 관찰로 남기며, 미사용 때문에 HTTP 검사를 생략하지 않는다.
- 복합 명령은 자동 읽기 계측에서 미분류될 수 있다. 별도 사후 감사는 알려진 문서 전체 내용의 정확한 출력 포함을 hash로 기록하고 성공/실패 명령 출력을 나눈다. 이는 모델이 문서를 소비하거나 이해했다는 증명이 아니다. 원래 24회 지표를 덮어쓰지 않는다.
- 짧은 스택별 읽기 안내를 소스에 반영하는 경우, 같은 새 artifact를 받은 compact와 brief 안내를 별도 전이 과제에서 비교한다. 문서 route 대신 notes route를 사용하는 143개 검사로 기존 예제를 그대로 따른 경우와 구분하고, 이전 24회와 토큰을 합산하지 않는다.
- 여기서 생성 횟수는 독립 Codex exec 세션 수다. 한 세션 내부의 API 요청 횟수는 측정하지 않으며, token usage는 CLI가 완료 이벤트에 보고한 집계값이다.
