# feature-standards 첫 버전 구현 계획

## 목적과 범위

AI가 반복 구현하는 기능을 명세·구현·공통 검증·적용 지침으로 배포한다. 첫 기능은 `browser-session-v1`의 로그인·로그아웃·내 정보 조회이다. Python/FastAPI와 Go/net/http 구현 및 공통 React 클라이언트를 제공한다. Java·Rust는 다음 확장 대상으로 명시하며 아직 지원한다고 표시하지 않는다.

## 단계

1. 공통 계약과 OpenAPI, 공통 API 테스트를 먼저 작성한다. 본문·origin·쿠키·서버 무효화·TTL·rate limit이 기준이다.
2. 독립 에이전트가 `implementations/python-fastapi`, `implementations/go-net-http`, `clients/react`를 각각 구현하고 자체 테스트한다. Git 작업은 주 에이전트만 수행한다.
3. 주 에이전트가 같은 계약 테스트를 두 서버에 실행하고 React 브라우저 테스트를 연결한다. 계약 차이는 명세와 검증을 기준으로 수정한다.
4. README, 적용 스킬, 기여·보안·업데이트 정책과 CI를 작성한다. 의존성을 고정하고 실제 실행 명령을 확인한다.
5. 전체 변경과 시크릿 포함 여부를 검토하고 작업 파일만 커밋한다. `jongko54/feature-standards` 비공개 GitHub 레포에 푸시한 뒤 원격 ref와 GitHub Actions 결과를 확인한다.

게시 단계 조정: 실제 HTTPS 푸시가 GitHub OAuth의 `workflow` scope 부족으로 거절되었고 기존 SSH 인증도 사용할 수 없었다. CI 정의를 `ci/github-actions.yml` 템플릿으로 포함해 코드 게시를 진행한다. 로컬 검증을 실행했으며 원격 CI는 미활성 상태로 보고한다. 원래 워크플로가 포함된 커밋은 로컬 `local/with-github-actions` 브랜치에 보존한다.

## 검증

- `python3 tests/conformance.py --backend all`
- 각 구현의 자체 테스트
- `npm ci`, `npm run build` 및 두 서버 대상 Playwright 테스트
- OpenAPI lint, `git diff --check`, CI

## 경계와 되돌리기

새 독립 레포에만 작성한다. 기존 프로젝트와 운영 환경은 변경하지 않는다. 배포는 범위 밖이다. 최초 레포는 비공개로 만든다. 세션은 메모리 저장이므로 운영 다중 인스턴스 지원으로 표현하지 않는다. 서버·브라우저 테스트 프로세스는 해당 작업 소유 프로세스만 종료한다.
