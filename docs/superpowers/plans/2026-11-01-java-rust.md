# Java·Rust 참조 구현 확장

## 목표

기존 `browser-session-v1` 계약을 유지하면서 Java/Spring, Rust/Axum 구현을 추가한다. React 클라이언트 하나와 같은 공통 API 시나리오를 네 서버에 적용한다. 단일 사용자·메모리 세션이라는 참조 범위는 유지한다.

## 역할과 단계

1. Java 에이전트: `implementations/java-spring/`에 Java21·Spring Boot·Maven wrapper 기반 서버, Argon2id, 자체 테스트, README를 작성한다. 산출물은 `target/auth-server.jar`이다.
2. Rust 에이전트: `implementations/rust-axum/`에 Axum 서버, Cargo.lock, 자체 테스트, README를 작성한다. 실행 파일은 `target/debug/feature-standards-auth`이다.
3. 검증 에이전트: 공통 runner의 backend 선택·빌드 재사용·시작 절차와 CI 템플릿을 확장한다. 기존 시나리오를 특정 언어에 맞춰 완화하지 않는다.
4. 주 에이전트: 문서와 적용 지침의 지원 목록을 정리하고 실제 자체 테스트·네 서버 공통 API·React 브라우저 통합을 실행한다. 신규 코드의 독립 리뷰 결과를 확인한다.
5. 작업 파일만 커밋·푸시하고 원격 main SHA를 확인한다. GitHub workflow 쓰기 권한은 별개이므로 CI는 기존 `ci/github-actions.yml` 템플릿으로 유지한다.

## 검증과 경계

- Java wrapper 자체 테스트·패키징, Rust test/fmt/clippy, 기존 Python·Go 자체 테스트
- OpenAPI 및 시나리오 매핑 검사, runner 회귀 테스트, React 단위 테스트·빌드
- `python3 tests/conformance.py --backend all --browser`: 네 구현에 같은 API·쿠키·React 시나리오 실행
- `git diff --check`, 원격 ref 및 working tree 상태

포트는 테스트 소유 프로세스만 사용하고 종료한다. GitHub 자격 증명·공개 범위·보안 권한은 변경하지 않으며 운영 배포도 하지 않는다. 필요한 JDK/Maven은 시스템 설정 변경 없이 공식 출처와 체크섬을 확인해 임시 도구 경로에 준비한다.
