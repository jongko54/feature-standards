# Spring 7 전환과 CLI 0.4.0 게시

## 승인된 범위

Spring 6.2의 공개 배포판에 남은 보안 권고를 해결하기 위해 Java 21을 유지하면서
지원되는 Spring Boot 4 / Framework 7로 전환한다. 검사 도구의 취약한 Python
의존성은 공식 native OpenGrep으로 교체한다. 인증 v1/v2/v3, 권한과 목록의
계약 및 보안 검사 실패 시 게시를 막는 기준은 유지한다.

게시 대상은 `feature-standards@0.4.0`이다. Java의 플랫폼 호환성 변경은 소스
후보와 과거 Maven 게시 버전을 명확히 구분한다. 과거 게시·보안 기록은 보존한다.

## 구현과 검증 순서

1. Java 구현, 별도 소비 앱, core 앱과 생성 템플릿의 지원 의존성을 함께
   전환한다. JSON 응답, 세션, CSRF와 저장소 장애 동작을 실제 테스트한다.
2. 공식 OpenGrep 릴리스의 플랫폼별 SHA-256을 고정하고 설치를 검증한다.
   기존 12개 규칙, 5개 언어의 양성·음성 fixture, 전체 소스 검사 및 실패 시
   차단 동작을 실제 엔진으로 확인한다. OSV와 Gitleaks 검사를 유지한다.
3. 카탈로그·AI 진입 문서·배포 도구를 새 Java 소스 버전과 일치시킨다.
   계약·native·HTTP·생성 앱·패키지 검사와 전체 보안 검사를 실행한다.
4. 검증한 변경만 커밋하고 main에 푸시한다. 동일한 정확한 SHA에서 원격
   기능 CI와 최신 보안 CI가 모두 성공했는지 확인한다.
5. 해당 SHA의 `feature-standards-v0.4.0` 태그로 기존 OIDC 게시 워크플로를
   실행한다. 게시 전 게이트와 아티팩트 해시 연결을 유지한다.
6. npm 레지스트리의 정확한 버전·integrity 및 새 소비 환경의 설치/CLI 실행을
   확인하고 결과를 기록한다. AI의 자연 검색 채택률은 이 배포의 검증 범위가 아니다.

## 완료 기준과 복구

수정된 코드의 관련 검사와 같은 SHA의 원격 CI가 통과하고, npm의 실제
0.4.0 아티팩트를 새 환경에서 설치·실행해야 게시 완료로 보고한다. 보안
발견이나 실행 오류는 해결 후 재검증하며 기존 게이트를 우회하지 않는다.
복구가 필요하면 이 변경의 Git revert를 사용한다. 이미 게시한 버전이나
태그를 덮어쓰지 않는다.

지원되는 패치 버전은 없다. 자세한 근거는

실패하는 동안은 릴리스 태그·npm 게시로 진행하지 않는다.
