# AI 발견과 SDK 선택 검증

## 목표와 경계

자연 검색에서 미추천된 사용자 관찰을 과장하지 않고, 발견·이름 검색·URL을
제공한 읽기·실제 통합을 서로 다른 조건으로 측정한다. 제품의 역할을 설명하는
공개 문서와 패키지 소개를 연결한다. 기능 계약, SDK 동작, 게시 버전, 보안
게이트는 변경하지 않는다. 새 웹 서비스, 계측 서버, 검색 순위 보장은 없다.

## 구현 순서

1. 기존 README·게시 기록·AI 실험과 Gemini CLI의 실제 실행 가능성을 확인한다.
2. 한국어·영어의 고정 질문과 네 단계의 관측 기준을 `evals/discovery/`에 둔다.
   이름 없는 조건은 브랜드·URL·로컬 소스를 제공하지 않는다. 같은 대화의
   후속 응답은 한 세션으로 취급하고, 실패·미확인·차단을 0과 구분한다.
3. `tools/discovery_observation.py`와 회귀 테스트를 추가한다. 실제 대화와 도구
   근거를 입력받아 조건별 분모·추천·출처·읽기·통합을 따로 집계한다.
   문자열 언급, 문서 경로, 모델의 자기 주장만으로 읽기나 SDK 통합을 세지 않는다.
4. `docs/what-is-feature-standards.md`에 목적·지원 범위·실행 예시·게시/후보
   버전과 한계를 영어로 설명한다. README, npm 안내와 snapshot에서 연결한다.
5. 가능한 실제 Gemini CLI 관측을 새 빈 작업 폴더에서 읽기 전용 웹 도구로
   실행한다. 기존 인증을 사용하고 설정·모델·권한을 임의 교체하지 않는다.
   CLI와 Gemini 웹 앱을 구분하며 인증/할당량 실패는 차단으로 보존한다.
6. 관련 Python 테스트·카탈로그 빌드/테스트·tarball 검사를 실행하고 정제된
   결과를 남긴다. 기존 AI 결과는 수정하지 않는다. GitHub 반영과 새 레지스트리
   게시는 구분하고, 이번 범위에 새 레지스트리 게시는 포함하지 않는다.

## 수용 기준

- 질문 문구·버전·해시와 모델/인터페이스·새 대화 여부·관측 시간이 기록된다.
- stage/질문/대화 단위를 확인하고 중복 대화로 성공률이 부풀지 않는다.
- 브랜드만 언급하거나 URL만 출력한 답변은 실제 문서 읽기/실행으로 승격되지 않는다.
- 조건별 미완료·미검토·차단이 보이고 웹 앱 결과와 CLI 결과를 합치지 않는다.
- 새 문서의 CLI 명령과 지원 버전은 현재 구현과 일치하고 과거 게시 상태와 구분된다.
- 변경 영향에 맞는 검증 결과와 실제 모델 관측의 한계를 별도 보고한다.

## 운영 반영과 되돌리기

실행 결과: 공개 소개·연결·snapshot·고정 질문·집계 도구와 회귀 검사를 추가했다.
Gemini CLI의 실제 첫 시도는 인증 차단으로 보존했다. Python 383개 중 350개
통과·33개 환경상 건너뜀, Node 52개와 tarball 설치 smoke가 통과했다.
관측과 한계는 `docs/adoption/2026-11-16-discovery.md`에 기록했다.

일반 문서·평가 코드 변경이다. 원격 반영 시 정확한 commit과 CI 상태를 확인한다.
되돌릴 때 이 변경의 문서·평가 코드만 revert하고 기존 실험과 사용자 상태는
보존한다. 검색 색인과 모델 추천은 비동기이며 반영 성공을 의미하지 않는다.
