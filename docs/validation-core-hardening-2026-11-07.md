# 코어 통합 고도화 검증

이번 변경은 인증·권한·목록을 실제 HTTP 앱에서 함께 재사용하는 범위와 Python PostgreSQL 목록 처리를 보강한다. CLI `0.4.0`과 Python 코어 `0.2.0`은 소스 후보이며, 기존 [코어 0.1.0 게시 기록](core-release-0.1.0.json)과 [CLI 0.3.2 게시 기록](npm-release-0.3.2.json)을 새 버전의 게시 증거로 사용하지 않는다.

## 동작과 지원 범위

- Python·Go·Java·Rust의 HTTP 소비 예제는 실제 로그인 쿠키와 현재 서버 측 membership을 사용한다. 권한 회수, 잘못된 주체, 제공자 장애, 위조 헤더, 다른 소유자·테넌트 접근과 노출되지 않은 목록 총계를 검사한다.
- Python 전용 `postgres-list-v1`은 값 바인딩과 SQL 식별자 허용 목록을 사용한다. 서버가 결정한 tenant/owner 범위를 count와 page에 동일하게 적용하고, 요청별 읽기 전용 repeatable-read 트랜잭션에서 실행한다. 호출자의 기존 트랜잭션을 종료하지 않는다.
- DB 컬렉션은 10,000행을 넘을 수 있지만 offset은 10,000 이하, limit은 100 이하이다. 다음 offset이 한도를 넘으면 남은 행이 있어도 `nextOffset`은 null이다. 전체 순회용 cursor와 요청 간 고정 snapshot은 제공하지 않는다.
- 소스 카탈로그는 26개 지원 조합을 제공한다. DB 목록은 Python에만 등록되며, 다른 스택으로 자동 대체하지 않는다.
- 소스 CLI의 선택적 `context --compact`는 필요한 계약·공개 API·소비 예제·규칙 문서와 해시로 안내한다. [26개 조합 측정](context-routing-size-0.4.0.json)에서 JSON 바이트가 52.96~65.68%, 중앙값 58.50% 줄었다. 참조 문서 내용과 실제 모델 토큰·속도는 이 수치에 포함되지 않는다.

## 로컬 검증

| 검증 | 실제 결과 |
| --- | --- |
| 5개 스택 공통 권한·목록 계약 | 스택별 공통 76개 벡터 및 자체 테스트 통과 |
| 실제 HTTP 소비 앱 | Python 12개, Go 8개 그룹, Java 9개, Rust HTTP 8개 및 CLI 2개 통과 |
| Python PostgreSQL | PostgreSQL 18.6에서 DB 16개 및 HTTP+DB 11개 통과 |
| Python DB 경계·시나리오 연결 | 경계 6개와 DB 16개, 총 22개를 명세에 연결해 검사 통과 |
| Python 독립 배포물 | 코어 0.2.0 후보 wheel을 새 소비 환경에 설치해 공통 76개 벡터와 psycopg 없는 선택 API import 통과 |
| CLI | 선택·신뢰 경계 21개 테스트, 실제 packed CLI의 26개 문맥과 Node export 검사 통과 |
| 통합 스킬 | 구조 검사와 4개 선택·신뢰 경계 시나리오의 독립 검토 통과 |
| Python 도구·하네스 | 고도화 통합 당시 164개 실행, DB 환경이 필요한 기존 33개 skip, 나머지 통과. 평가기 보완 후 관련 auth/core 및 재검사 경계 49개를 독립 재실행해 통과. |
| 정적 검사 | 변경 범위/CI의 Ruff, Go vet/race, Rust fmt/clippy, workflow 두 사본 일치와 diff 공백 검사 통과 |

로컬 DB 검사는 작업 전용 임시 PostgreSQL 또는 무작위 소유 schema만 사용했다. 원래 인증 DB와 릴리스 worktree는 유지했다. 테스트·데모 연결에서 libpq 환경변수에 의한 주소 우회는 I/O 전에 거절하며, 빈 값도 검사한다. 연결 함수를 호출하지 않는 sentinel 회귀 테스트와 독립 재검토로 확인했다.

추가로 전체 Python 코어 폴더를 대상으로 확대한 스타일 검사는 변경하지 않은 기존 authorization 파일 등에서 6개 지적을 보였다. 이번 변경 범위의 Ruff 통과를 전체 폴더의 무결점으로 확대하지 않는다.

## AI 평가와 원격 검증

[통합 평가 도구](../evals/core/README.md)는 공개 CLI 0.3.2와 고정 구현 소스를 사용한다. 각 스택·조건에 1회씩 총 8회 실행한 원본 결과와 평가기 보완 후 생성물 재검사를 분리한다. 작은 표본, 공유 캐시와 동시 호스트 작업 때문에 일반적인 속도·토큰 개선을 주장하지 않는다. 새 compact 모드는 이 실험의 평가 대상이 아니다.

[원본 8회 기록](../evals/core/results/2026-11-07-catalog-smoke-v1.json)은 7/8 통과이며, Python catalog 한 건은 캐시 symlink 검사에서 HTTP 실행 전에 막혔다. 모델 추가 호출 없이 저장된 생성물 8개를 같은 보완 정책으로 [재검사한 결과](../evals/core/results/2026-11-07-catalog-replay-v1.json)는 5/8 통과다. Python catalog는 생략한 캐시 때문에 offline 빌드가 실패했고, Go 두 건은 HTTP 143개 검사를 통과했지만 생성 파일 바이트 보존 검사를 통과하지 못했다. 변경 원인은 확인되지 않아 단정하지 않는다. 원본 결과·trace·참조 소스·생성 소스의 전체 8개 전후 해시 일치를 확인했다. 시간·토큰과 원래 성공률을 재검사 결과로 덮어쓰지 않았다.

원격 CI 결과는 최종 소스 커밋의 실행 상태로 확인한다. 패키지 게시, 브라우저 UI의 새 기능 검증, 운영 앱 배포와 보안 감사는 별도의 증거가 필요하다.
