# 실제 모델의 읽기 경로·토큰·재사용 실험

총 **37개 독립 Codex exec 세션**을 실행했다. 원래 읽기 비교 24회는 HTTP 23/24, 사용 지시 없는 관찰 4회는 3/4, 짧은 가이드 비교 8회는 8/8이다. PostgreSQL 원본 1회는 검사기 오탐으로 HTTP 검사 전에 멈췄고, 이후 같은 생성물의 별도 재검사가 149개 검사를 통과했다. 과제·판정이 다른 결과를 합쳐 단일 성공률로 제시하지 않는다.

2026-11-08의 1차 비교는 **새 Codex exec 세션 24회, 원본 HTTP 통과 23/24**다. 문서 진입 대비 compact 안내의 입력 토큰 합계는 **19.032% 감소**했지만, 캐시되지 않은 입력은 **16.927% 증가**, 출력은 **12.933% 증가**했다. 이 표본으로 비용 절감이나 모든 AI의 개발 속도 향상을 주장하지 않는다.

[원본 정제 결과](../evals/core/results/2026-11-08-reading-candidate-v1.json)와 [별도 사후 감사](../evals/core/results/2026-11-08-reading-postrun-audit-v1.json)를 함께 제공한다. raw trace, 생성 앱, 로그와 fixture는 공개하지 않는다. 이전 CLI 0.3.2의 7/8 smoke 및 5/8 재검사 결과는 [기존 기록](../evals/core/README.md)에 보존한다.

## 고정한 조건

- Python·Go·Java·Rust × manual/full/compact × 2회 = 24개 독립 세션. 세 조건 모두 기존 패키지 사용을 명시적으로 요청했다.
- 같은 인증 memory v1·RBAC·메모리 목록 과제, 읽기 전용 소스, CLI 0.4.0 로컬 후보 tarball, 도구 환경을 제공하고 최초 읽기 안내만 바꿨다. full과 compact 안내의 차이는 `--compact` flag다.
- 언어별 시작 조건을 회전하고 두 번째 반복은 해당 언어의 역순이다. 모델 실행은 직렬이며 정상 빌드로 의존성 캐시를 사전에 준비했다. 공유 호스트 캐시·서버 prompt cache는 완전히 통제하지 못했다.
- 요청 모델 `gpt-6.1-sol`, Codex CLI `0.167.0`, 실행별 제한 600초. 실제 모델 ID는 trace에 없어 unknown이다. 모델을 자동 교체하지 않았다.
- 과제 소스 `78686cc60ec18c13e093158a1330e323d8b7c893`, 실행기 `83b7633b06e1a60376cc671a4325b107d131e088`. tarball SHA-256은 `7ab98af2d4854743bd1641d38f101df9464cad129a409179f402b9f46105b71b`이며 clean source에서 만들었다. registry 배포를 측정한 것이 아니다.

세션 수는 모델 내부 API 호출 횟수가 아니다. usage는 CLI의 완료 이벤트가 보고한 집계값이며, 반복 문맥을 포함한 입력 토큰 수다. 고유 프롬프트 길이나 청구 금액으로 해석하지 않는다.

토큰 비교의 범위는 각 통합 과제를 수행한 Codex exec 세션이다. 실험을 조정한 상위 에이전트·독립 리뷰 에이전트의 토큰, 일반 빌드·HTTP grader·CI 운영 비용은 이 비교에 포함하지 않았다.

## 실제 토큰 비교

같은 언어·반복 번호의 완전한 usage 쌍을 묶어 `(기준 합계−비교 합계)/기준 합계`로 계산했다. 실패한 실행도 완전한 usage가 있으면 포함한다. 음수는 토큰 증가다.

측정값은 문서 읽기뿐 아니라 코드 생성·도구 오류·자체 실행을 포함한 통합 세션 전체의 usage다. 안내 파일의 크기만 비교한 값이 아니며, 특정 문장 하나의 절감 효과를 분리하지 않는다.

| 기준 → 비교 | 완전 쌍 | 입력 절감률 | 캐시 입력 절감률 | 비캐시 입력 절감률 | 출력 절감률 | 입력+출력 절감률 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| manual → full | 8 | -0.950% | -0.522% | -8.733% | -14.339% | -1.036% |
| manual → compact | 8 | 19.032% | 21.008% | -16.927% | -12.933% | 18.826% |
| full → compact | 8 | 19.794% | 21.418% | -7.536% | 1.230% | 19.659% |

manual → compact의 입력 합계는 6,644,344 → 5,379,772, 비캐시 입력은 345,976 → 404,540, 출력은 43,168 → 48,751이다. 입력 절감률의 쌍별 중앙값은 10.485%다. 위 19.032%는 합계 기준이며 개별 실행이 모두 그만큼 줄었다는 뜻이 아니다. 두 조건이 모두 성공한 7쌍의 수치는 JSON에 별도로 제공하며 전체 8쌍의 결과를 대체하지 않는다.

| 언어 | manual → compact 쌍 수 | 입력 절감률 | 입력+출력 절감률 |
| --- | ---: | ---: | ---: |
| Python | 2 | 35.455% | 35.366% |
| Go | 2 | 16.260% | 16.089% |

`input`에 캐시 입력이 포함되므로 캐시를 total에 다시 더하지 않는다. `uncached=input−cached`, `total=input+output`이다. raw usage의 reasoning output은 이미 output의 일부이므로 더하지 않는다. 별도 감사에 추가 카운터를 남겼고, 관측 cache-write input은 전체 0이다. 이 해석은 [OpenAI의 usage 예제](https://developers.openai.com/cookbook/examples/agent_optimization/optimizing_agents_for_cost_and_quality#metrics-helpers)를 따른다.

## 실제로 읽고 재사용했는가

원본 자동 계측은 안전하게 분류 가능한 실제 argv와 문서 경로만 인정한다. 복합 shell 명령은 미분류될 수 있어 0을 미사용으로 해석하지 않는다. 별도 사후 감사는 고정 whitelist 문서의 전체 바이트가 도구 출력에 포함됐는지 SHA-256으로 확인했다. 24개 모두에서 전체 문서 출력이 관측됐고, full·compact는 각각 8개 모두에서 선택한 세 기능의 문맥 데이터가 출력됐다. 이는 CLI 실행 출처, 모델의 소비·이해 또는 내부 추론을 증명하지 않는다.

동일한 수정 checker로 생성물 24개를 정적 재검사하여 모두 공개 API 호출 단서를 확인했다. 이 결과는 실제 경로 실행의 인과관계나 구현 중복이 없다는 증명이 아니다. 별도의 HTTP grader가 세션 폐기, 권한 철회, 제공자 장애, 비공개 총계, 타입·정렬·페이지와 헤더를 검사한다. 원본에서 통과한 23개는 각각 143개 assertion을 통과했다.

[독립 소스 경로 감사](../evals/core/results/2026-11-08-reading-source-route-audit-v1.json)는 24개 모두의 build/start 선언부터 제품 handler까지 확인했다. 인증·권한·목록 72개 연결 모두 공개 라이브러리 호출로 이어졌으며 미사용 import만의 증거나 자체 기능 엔진으로 대체한 경우는 발견하지 못했다. membership 파일 처리·응답 projection 같은 앱 glue는 직접 작성한 것으로 구분했다. 파일별 해시와 상대 행 번호를 남겼고, 이 역시 런타임 계측을 대신하지 않는다.

남은 Java compact 1회는 `"/**"` 문자열을 주석 시작으로 오인한 checker 때문에 HTTP 검사 전에 중단됐다. 문자열을 보존하고 파일별로 주석을 제거하는 수정 및 회귀 검사를 추가했다. 원본 outcome·토큰·시간은 그대로이며, 과거 임시 경로의 독립적인 실제 `pwd` 증명이 없어 HTTP 재실행을 하지 않았다. **정적 24/24와 HTTP 23/24는 다른 결과다.**

## 별도 PostgreSQL 관찰

Python PostgreSQL 목록 통합의 [원본 1회 결과](../evals/core/results/2026-11-08-postgres-candidate-v1.json)는 `postgres-library-reuse-evidence-missing`으로 HTTP 검사 전에 중단됐다. 사용한 소스·tarball은 notes 비교와 동일하다. 소스에서는 `adapter()`가 `PostgresListing`을 반환하고 제품 경로에서 `store=adapter(); store.page(...)`를 호출한다. 직접 constructor/변수 alias만 추적하던 평가기가 팩토리 반환을 인식하지 못한 오탐이다. 원본 실패·토큰·시간은 보존하고 검사기 보완 및 별도 생성물 진단을 분리한다.

인자·decorator가 없고 공개 constructor를 바로 반환하는 작은 sync 팩토리만 인식하도록 좁게 보완했다. 정상 변형의 RED→GREEN 및 조건부·중첩·비동기·다른 팩토리의 제외 회귀를 검증했다. [별도 생성물 진단 2회](../evals/core/results/2026-11-08-postgres-artifact-diagnostics-v1.json)는 새 모델 세션 0회다. 첫 진단은 원래 `--offline` 빌드 캐시에 `hatchling`이 없어 실패했다. 두 번째는 해당 캐시에 빌드 도구 `hatchling 1.33.0`을 준비한 뒤 **149개 HTTP 검사를 통과**했다. 생성 코드·lockfile·run 지침은 바꾸지 않았다. 준비된 캐시를 사용하는 환경의 역량 관찰이며 깨끗한 offline 환경에서의 재현 성공으로 확대하지 않는다.

143개 기존 검사 뒤 10,001행을 추가하여 가시 총계 10,003, offset 10,000의 `bulk-10000`, 상한을 넘는 nextOffset의 null 및 헤더를 확인했다. 인증은 memory v1이고 목록만 PostgreSQL이다. 소유한 임시 클러스터와 SELECT 전용 앱 역할을 사용했고 운영 DB·기존 공유 테스트 DB·SMTP·배포는 건드리지 않았다. 성공한 실제 `pwd`로 증명된 부재 임시 경로만 독점 복원했다. 양쪽 진단의 원본 result·trace·reference·generated 해시가 보존됐으며 복구본도 삭제 전에 검사했다. 두 번째는 임시 DB·역할·복원 경로 정리까지 성공했다. 원래 1회가 성공했다는 뜻은 아니다.

## 실행 범위와 읽기 안내

라이브러리 사용을 지시하지 않는 discovery 4회, 같은 notes 과제에서 compact와 언어별 짧은 가이드를 비교하는 8회, Python PostgreSQL 목록 통합 1회는 각각 별도로 기록한다. 원래 24회에 합산하거나 다른 버전·과제의 토큰과 짝짓지 않는다. discovery는 저장소와 패키지를 이미 제공한 상황의 선택 관찰이며 전 세계 AI의 채택률이 아니다.

선택형 읽기 안내는 [Python](ai-briefs/python.md)·[Go](ai-briefs/go.md)·[Java](ai-briefs/java.md)·[Rust](ai-briefs/rust.md)의 brief다. 소비 예제에서 필요한 API만 따라가고, 프로필 ID와 파일명을 구분하고, 불필요한 전체 구현·반복 offline 설치를 피하도록 안내한다. CLI 소스 후보에 문서로 번들했으며 기존 full/compact 기본 경로는 유지한다. 위 유사 과제에서 감소를 관측했지만 모든 프로젝트의 효율 개선을 보장하지 않는다. v2/v3·DB 목록·React UI는 이 brief의 범위가 아니다.

## 한계

언어·조건별 두 번, 한 모델·한 과제 계열의 탐색적 표본이다. 캐시 변동, 순서 효과, 생성물 길이와 독립 빌드 비용이 남아 있다. 모델 내부 알고리즘, 외부 이용자 수, 일반적인 통계적 효과, 운영 성능·보안 감사와 React UI를 측정하지 않았다. 새 Python DB 목록 API도 1차 24회 비교에 포함되지 않았다.
