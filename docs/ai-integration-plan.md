# AI 통합 고도화 계획

승인 범위: 기존 인증 계약을 유지하면서 AI의 탐색·선택·재사용·검증을 개선한다. 언어 전체의 공인 표준이나 모델 내부 알고리즘 분석으로 표현하지 않는다.

1. 저장소 루트 `feature-standards.json`에 프로필, 스택, 공개 API, 소비 예제, 검증 명령을 구조화한다. 스키마·경로·프로필·공개 진입점의 drift를 검사한다.
2. `skills/integrate-auth/`를 `.agents/skills/`에서 자동 발견하게 연결한다. 진입점은 필요한 프로필·스택 문서만 선택하고, 계정·메일 세부 불변식은 조건부 참조로 옮긴다.
3. Go를 import 가능한 패키지와 실행 진입점으로 분리하고, Java는 라이브러리 JAR를 제공한다. Go·Java·Rust에 인증 로직을 복사하지 않는 별도 소비 프로젝트와 로그인·보호 API·로그아웃 후 이전 세션 거절 검증을 추가한다.
4. `evals/auth/`에 동일 통합 과제, 결정적 결과 검사, 모델 실행 trace와 시간·토큰·명령 수 수집을 추가한다. 실행 전용 임시 디렉터리에서 baseline과 skill 조건을 비교한다. 모델 평가를 일반 구현 테스트와 구별한다.
5. 계약·manifest·평가 도구 회귀, 언어별 자체 검사, 소비 예제, 공통 API·React 빌드·브라우저를 실행한다. 현재 변경 범위와 실제 결과를 기록하고 원격 push·CI 상태를 별도로 확인한다.

모델 평가는 설치된 CLI의 지원 옵션을 확인하고 기존 사용자 인증을 사용한다. 공급자 비밀·운영 DB·실제 수신자는 사용하지 않는다. 반복 횟수·시간을 제한하고 실행 실패나 미측정 항목도 결과로 남긴다. 예제용 로컬 패키지를 레지스트리에 게시하지 않는다.

롤백: 이 작업의 커밋을 되돌리면 기존 인증 계약과 DB 데이터는 유지된다. DB migration·운영 배포는 추가하지 않는다.

## 진행 상태 (2026-11-03)

- 스택 5개·프로필 3개 manifest, 자동 탐색 symlink와 조건부 참조를 구현했다.
- Go·Java·Rust 독립 소비 예제와 공개 API 오류 회귀를 구현했다.
- v1/v2 네 서버 HTTP·Secure 쿠키·각 32개 브라우저 검사, v3 계정 HTTP·12개 브라우저·혼합 계정 경합 검사를 통과했다.
- 실제 모델 평가 8/8 성공과 HTTP 19개씩 통과, 사용량·시간·문맥 참조를 측정했다. 최종 원격 push·CI 확인은 진행 중이다.
